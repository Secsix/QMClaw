# S21 照片读数（人工辅助）

## 定位：仅人工，不进自动链路

读截图这件事需要**看图**，而自动链路里的模型未必有图像输入能力；
更重要的是：从截图上读出的数字**不是测量结果**，它是别人以前测的、现在被抄一遍。
所以这条流程只有两个合法用途：

1. 人工核对（"图上这批比特的频率是多少"）；
2. 把人工确认过的数字，经**受控写入**通道落到硬件。

**禁止**：把截图读数当成新的测量证据写进状态机。状态只认有 `run_id` 与 `dataset_ids` 的运行。

## 第一步：读数

用仓库里的辅助脚本（人工在场时跑，输出 CSV / 报告 / 标注核对图）：

```bash
python tools/s21_photo_reader/run.ps1            # 单张 / 批量见脚本内说明
```

读图时务必向人说明三件事：

- 标在比特旁的数字是**波谷所在频率**（GHz），已与 X 轴刻度逐点校验；
- Y 轴是**原始读出计数**，不是归一化 S21；附加的"深度/基线"是栅格估读，误差约 ±5~10%；
- 图底汇总列表与图内标注应互为校验；不一致时以人眼核对为准。

## 第二步：写回（只能走服务）

**不要**在技能里执行任何向硬件寄存器赋值的代码。写回统一走测控微服务：

```
POST http://localhost:3002/api/quantum/qubit/set_params
{"name": "q3", "params": {"f10": 6.2835e9}}
```

- 该端点受**写闸门**控制（`allow_set_params` 默认关闭）。闸门没开就返回拒绝，
  这不是故障，是设计——需要由人显式开启并在现场确认安全。
- 写之前先读一次当前值（`GET /api/quantum/qubit/params?name=q3`），把"旧值 → 新值"写进汇报。
- 一次只改一个比特的少数参数；批量改动要人逐条确认。

## 第三步：汇报格式

| 比特 | S21 波谷（GHz） | 当前 f10（GHz） | 是否一致 | 处理 |
| --- | --- | --- | --- | --- |
| q3 | 6.2835 | 6.2831 | 差 0.4 MHz | 人工决定是否写回 |

必须写清：读数来源是截图（不是本次测量）、写回是否真的执行（闸门是否开启）、
以及"图上被标注遮挡/识别存疑"的部分。

## 坑

1. **截图不是数据**：它不能进证据链，也不能用来推进状态。
2. **图上标的是波谷频率**，不是"波谷幅值"；两者单位不同，别混。
3. **写回前先读**：不做"旧值 → 新值"对照的写入，事后无法追责。
4. **闸门关闭时不要绕**：不要用其它脚本、其它端口、直接连硬件来"绕过"写闸门。
