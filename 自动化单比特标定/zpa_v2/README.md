## 旧算法为何漏检

旧算法198个数据输出26个正常候选，与修正后的人工标签相比：TP=24、FP=2、FN=57、TN=115。正常召回率29.63%，精确率92.31%。误报为02346、03645。

旧算法强制至少7个内部谐振谷、完整扫描、向下二次曲线和两侧转折，无法覆盖人工接受的截断支路、平直/弱调制、稀疏频率采样和部分扫描。例如00013/00037/00090的支路多处到达频率边缘；00736的最小值频点在全部ZPA上不变，但用户仍判正常；00747仅4个频率点。由此不能继续简单降低单一抛物线门槛。

## 修改方案

- `../classify_zpa_datavault.py` 是新版入口；旧版保留为 `../classify_zpa_datavault_v1.py`。
- `../zpa_features.py` 从真实二维幅度数据提取数值特征：谐振谷轨迹范围/标准差/跳变、边缘比例、局部谐振对比度、沿频率和ZPA方向的变化/曲率、缺测比例、采样密度，以及归一化16×16二维形状。
- 频率坐标按每个文件自己的范围进行插值；不输入绝对频率、文件编号、文件名或比特名。支持频率窗口移动，但仍受训练数据分布和采样覆盖限制。
- 分类器为固定配置ExtraTrees（500棵树，min_samples_leaf=2，max_features=0.7，class_weight=balanced，seed=42）。阈值固定0.5，0.35–0.65为人工复核区间；未根据验证集优化阈值。
- 零有效幅度、无法形成最基本二维扫描的输入硬性拒绝。
- 模型导出成 `model.json`，推理不读取人工标签，不使用pickle。
- **normal_score是树模型输出分数，不是已校准的统计概率或物理正确率。** 正常结果只代表图像/数据形态符合当前人工标准，不代表已确认量子比特频率。

## 运行

使用已具备numpy、scipy、h5py、scikit-learn的本机Python：

```powershell
python train_zpa_model.py --directory . --labels zpa_manual_labels.json --out zpa_v2
python classify_zpa_datavault.py . --model zpa_v2/model.json --out zpa_v2/predictions
python test_zpa_classifier.py
```

训练需要scikit-learn；推理仅需numpy/scipy/h5py及模型文件。输入HDF5仅只读打开。

输出：
- `predictions/normal_ids.txt`：阈值>=0.5的正常预测（当前81个，完全等于人工名单）。
- `predictions/auto_accept_ids.txt`：剔除不确定区间后的自动正常候选。
- `predictions/review_ids.txt`：不确定样本（当前批次无落入该区间的数据）。
- `predictions/classification.csv`：完整198文件最终模型预测。
- `validation.csv` / `validation.json`：198文件的训练预测、按比特分组留出预测、折编号、人工标签、复核建议；评估泛化应看这里。
- `feature_importance.json`：重要特征，前三为支路变化范围、轨迹标准差、频率方向响应变化。

测试已通过：JSON模型与sklearn预测分数一致；当前81/117标注回归；重命名/编号无关性；行顺序无关性；绝对频率平移不变性；零信号拒绝；198条留出验证记录完整。

## 适用边界与后续测量

本版本专用于当前LabRAD DataVault结构（freq、zpa独立轴，Amplitude为f2），不是任意HDF5通用识别器。插值补齐缺失数据同时保留缺测特征，但不代表恢复真实信号。部分扫描、弱信号、分布外数据需要人工复核。无可辨转折的正常图不能强行输出sweet point；本版本不再根据分类结果虚构sweet ZPA或比特频率。

依据论文第5.1节图5.6，磁通通过比特频率改变腔的色散位移；读取谐振频率与比特跃迁频率不是同一个量。下一步若曲线触边，先扩展读取频率窗口；若平直/弱调制，先调整功率、ZPA扫描密度并复核相邻比特影响；有明确转折后才定位工作点，随后按第5.2节固定读取条件扫描XY驱动频率，再以Rabi验证。
